# ai agent

Полуавтоматический помощник для поиска клиентов среди автосервисов Екатеринбурга. Ищет публичные сведения через веб-поиск, проверяет собственный сайт и конкурентов, готовит персональное предложение сайта за 25–35 тысяч ₽ и концепт первого экрана. Пользователь проверяет результат и отправляет сообщение сам.

## Запуск

Требуется Node.js 24 и npm. Команды выполняются из `/workspace/casino` (или корня вашего checkout).

```bash
npm_config_devdir=/workspace/.cache/node-gyp npm ci --cache /workspace/.npm-cache
npm run auth:setup
npm run dev
```

В отдельном терминале из той же директории:

```bash
npm run worker
```

Сервер слушает только loopback на порту 3000. Для смены порта: `npm run dev -- --port 3002`. Worker необходим для обработки очереди: открытие страницы его не запускает. После перезапуска оба процесса используют сохранённую SQLite-базу. Для production-сборки: `npm run build`, затем `npm run serve` — эта команда запускает сервер и worker вместе. Пароль находится в приватном `data/admin-access.txt`; не отправляйте его в чат.

## Подключение AI

В облачной среде добавьте в защищённых настройках секрет **AI_PROVIDER_API_KEY** для HTTPS-адреса **api.openai.com**. Нужны баланс, доступ к Responses API с `web_search`, структурированным ответам и Images API. После применения настроек перезапустите оба процесса. Не отправляйте ключ в чат или Git.

Для обычного локального запуска можно создать игнорируемый `.env.local` на основе `.env.example` и ввести ключ там. Настройки моделей необязательны: `AI_TEXT_MODEL=gpt-5-mini`, `AI_IMAGE_MODEL=gpt-image-2.5-flare`. Модели должны быть доступны вашему аккаунту. Приложение не умеет подтверждать права только по наличию ключа — фактические ошибки показываются в истории заданий.

Без ключа работает сохранение компаний вручную, редактирование сообщения и отметка статуса. Автоматический поиск, анализ и изображения дают явную блокировку. Ручная ссылка не скачивается приложением: внесите проверенные сведения самостоятельно, затем запустите анализ. Повторный запуск заблокированного этапа доступен после настройки ключа.

Подробнее об источниках, API и проверках: [docs/providers.md](docs/providers.md).

## Рабочий процесс

1. Запустите поиск по Екатеринбургу: от 1 до 20 автосервисов. Источниками могут быть 2ГИС, Яндекс Карты, открытые каталоги и сайты компаний; покрытие не гарантируется.
2. Во вкладке «Запуски» проверьте прогресс и ошибки. Отмена прекращает следующие этапы; уже отправленные внешние запросы могут тарифицироваться.
3. В карточке компании проверьте наблюдения и ссылки. «Сайт не найден» означает результат ограниченного поиска, а не доказательство его отсутствия. Машинный пересказ источника требует проверки.
4. Отредактируйте сообщение и сохраните его. Повторный анализ сохраняет ваши правки и проверенные сообщения. Для загруженной устаревшей версии сервер вернёт конфликт, чтобы не потерять чужое или фоновое изменение.
5. После анализа отдельно создайте референс. Это концепт, а не существующий сайт. Перед передачей проверьте текст, услуги и визуальные детали.
6. Скопируйте сообщение, отправьте через подходящий канал самостоятельно и отметьте «Связались».

Стоимость API пока **неизвестна**, а не равна нулю: показаны попытки и доступные токены, точные расходы проверяйте в биллинге OpenAI. Ошибки, отмена и повторные попытки тоже могут привести к расходам.

## Данные и доступ

- База: `data/agent.sqlite`, изображения: `data/artifacts/`. Пути меняются через `DATABASE_PATH` и `ARTIFACT_DIR`.
- Эти данные, `.env.local`, зависимости и результаты тестов исключены из Git. Для резервной копии остановите процессы и скопируйте весь `data/`, включая SQLite WAL/SHM, если они есть.
- Приложение предназначено для одного пользователя. Вход по APP_PASSWORD обязателен, страницы и data API защищены серверными сессиями. Публичный HTTPS origin должен быть настроен точно; изменения требуют совпадения Origin.
- API-ключ используется только сервером; ошибки провайдера не пересылаются в браузер целиком. Приложение не скачивает произвольные URL и не отправляет сообщения бизнесам.
- Не создавайте дополнительные Git worktree для этой облачной задачи: текущий checkout уже изолирован.

## Проверки

```bash
npm test
npm run typecheck
npm run build
npm run test:e2e
```

Браузерные тесты используют установленный `/usr/bin/chromium`; иной путь задаётся через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Если системного браузера нет, установите Chromium через Playwright и его системные зависимости по официальной инструкции; конфигурация использует стандартный Playwright-браузер при отсутствии системного пути.

E2E запускает приложение на порту 3100 и тестовый worker на 3101, использует только `data/e2e-agent.sqlite` и `data/e2e-artifacts/`. При каждом запуске очищаются исключительно эти тестовые данные. Синтетические провайдеры находятся в `tests/fixtures/`; production worker их не загружает. В тестовом интерфейсе есть заметная пометка. Успешный E2E не подтверждает работу реальных источников или доступ к внешнему API.

## Текущая граница проверки

Реальные запросы поиска, анализа и изображений требуют ключа, которого в среде на момент разработки нет. Поэтому сбор реальных компаний и качество референсов ещё не проверены. Автоматическая рассылка, CRM, платежи и публичное размещение не входят в эту версию.
