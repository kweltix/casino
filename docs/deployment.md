# Защищённый запуск и Render

## Локально

Из корня проекта выполните `npm run auth:setup`. Команда создаёт случайный пароль в приватном игнорируемом `data/admin-access.txt` и `APP_PASSWORD` в `.env.local` (режим файлов 0600). Пароль не выводится в журнал и не попадает в Git. Существующий пароль не заменяется. Не отправляйте эти файлы в чат или репозиторий.

После `npm run build` команда `npm run serve` запускает production-сервер и фоновый worker вместе. По умолчанию сервер слушает loopback, порт 3000; обе части останавливаются, если одна неожиданно завершится. Для разработки по-прежнему доступны `npm run dev` и отдельно `npm run worker`.

Локальный запуск в удалённой облачной среде не даёт публичной ссылки. Адрес localhost на вашем устройстве не ведёт в эту среду. Проверенные сервисы временных туннелей (trycloudflare, localtunnel, localhost.run) вернули сетевой proxy403; внешний доступ через них не подготовлен.

## Render

В репозитории есть `Dockerfile` и `render.yaml`. Схема — **один платный Web Service с одним постоянным диском**, один экземпляр. Это важно: SQLite нельзя разделить между независимыми Render Web Service и Background Worker, поэтому два процесса запускаются под общим супервизором в одном контейнере. Это не бесплатный тариф; актуальную стоимость и условия проверьте перед созданием в Render.

1. Войдите в [Render Dashboard](https://dashboard.render.com/), подключите GitHub и разрешите доступ к `kweltix/casino`.
2. Создайте Blueprint из ветки **ai-agent-initial-version**, в которой находится `render.yaml`. Проверьте платный план, регион и постоянный диск 1 GB, затем подтвердите создание.
3. В защищённых переменных Render задайте **APP_PASSWORD**: собственный уникальный пароль минимум из 16 символов (лучше случайный). Можно использовать локально созданный пароль, введя его в Render самостоятельно; не отправляйте значение в чат.
4. Для работы AI добавьте **AI_PROVIDER_API_KEY** и обеспечьте баланс/доступ к OpenAI. Для просмотра приложения этот ключ необязателен: AI-этапы будут явно заблокированы.
5. Render обычно задаёт `RENDER_EXTERNAL_URL`. Если эта переменная отсутствует или используется собственный домен, задайте **APP_ORIGIN** равным точному HTTPS-адресу приложения без пути, query и fragment. Чужие Host/Origin отклоняются. Не используйте wildcard.
6. Дождитесь успешного deploy и `/api/health`. Откройте HTTPS-адрес, который выдаст сам Render, войдите по паролю. Проверьте, что без входа `/api/workspace` возвращает 401, а после входа доступны компании. Затем проверьте малый реальный AI-запуск.

Render и его аккаунт не подключены к этому чату: создание платного сервиса, ввод пароля и получение настоящего публичного URL требуют действия в аккаунте. Blueprint и Dockerfile не означают, что сервис уже опубликован.

## Защита и эксплуатация

- Вход закрывает страницу и все data API, включая картинки. Только минимальный `/api/health` доступен без входа.
- Без корректного `APP_PASSWORD` сервер `serve` не запускается; при других способах запуска данные всё равно закрыты.
- Сессия — случайный 256-битный токен в HttpOnly SameSite=Strict cookie на 8 часов. Для HTTPS — Secure cookie с префиксом __Host-. В базе хранится хэш токена. Смена APP_PASSWORD и перезапуск отзывают прежние сессии; выход удаляет текущую сессию в базе.
- Пять попыток входа за 15 минут ограничиваются глобально и сохраняются в SQLite. Это защищает единый вход от перебора, но посторонний может временно исчерпать лимит входа. Уже открытые сессии продолжают работать.
- Render-образ сначала готовит владельца каталога диска, затем сбрасывает root до UID/GID 1000 перед запуском приложения и worker. Не масштабируйте контейнер на несколько экземпляров с локальной SQLite.
- База, референсы и сессии находятся на `/app/data`. Сохраняйте резервные копии диска; удаление сервиса/диска может удалить данные.
- Автоматическая отправка сообщений бизнесам отсутствует.
