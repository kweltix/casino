# AI Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить проверяемый полуавтоматический поиск клиентов среди автосервисов Екатеринбурга с анализом, сообщением и концептом сайта.

**Architecture:** Next.js обслуживает интерфейс и серверные маршруты; SQLite хранит компании, источники и задания. Отдельный worker забирает задания из базы. Внешние провайдеры подключаются через серверные адаптеры; отсутствие ключа или доступа явно блокирует соответствующий этап.

**Tech Stack:** Node.js 24, TypeScript, Next.js, React, SQLite через better-sqlite3, Zod, Vitest, Playwright. Версии зависимостей фиксируются lockfile после проверки совместимости.

**Spec:** `docs/superpowers/specs/2026-10-28-ai-agent-design.md`

## Global Constraints

- Первый запуск обрабатывает до 20 компаний: независимые автосервисы Екатеринбурга.
- Предложение сайта за 25–35 тысяч рублей; отправка сообщений только пользователем.
- Ключи доступны только серверу через защищённые настройки.
- Неограниченный бюджет не означает бесконечные задания.
- Автоматический сбор только через проверенный разрешённый способ, без обхода CAPTCHA.
- Отсутствие ссылки не доказывает отсутствие сайта; неизвестная стоимость не равна нулю.
- Разрабатывать в существующем изолированном checkout; не публиковать приложение автоматически.

## Review Focus

- Одинаковые названия у разных сервисов: не объединять компании без совпадения адреса или идентификатора источника (Task 1).
- Внешний текст с инструкциями: не исполнять инструкции из карточек и не принимать неподтверждённые выводы модели (Task 3).
- Перезапуск worker во время работы: восстанавливать просроченную аренду задания с ограничением попыток (Task 2).
- Недоступный источник или ключ: показывать конкретную блокировку, не подставлять демонстрационные результаты (Task 3).
- Загрузка страницы с другого origin и доступ к серверным ключам: блокировать изменения из чужого origin, не выдавать секреты клиенту (Task 4).

### Task 1: Хранилище и контракты данных

**Files:** `package.json`, `package-lock.json`, `tsconfig.json`, `.gitignore`, `.env.example`, `src/domain/types.ts`, `src/domain/validation.ts`, `src/server/db.ts`, `tests/db.test.ts`.

**Interfaces:** `createStore(path: string): Store`; Store предоставляет `upsertCompany(input: CompanyInput): Company`, `createRun(input: RunInput): Run`, `getRun(id: string): Run | null`, `listCompanies(): Company[]`, `close(): void`. Company содержит id, sourceId, name, address, websiteStatus, sources; Source содержит url, fetchedAt, excerpt. RunInput содержит city, niche, limit (1–20). Дополнительные типы следующих задач экспортируются из `types.ts`.

- [ ] Добавить минимальный проект и тест `tests/db.test.ts`: повторная запись sourceId возвращает тот же id; одинаковые названия с разными адресами остаются разными; limit 0 и 21 отклоняются; данные сохраняются после повторного открытия базы. Запустить `npx vitest run tests/db.test.ts`: ожидать ошибку отсутствующей реализации.
- [ ] Реализовать Store, миграции, валидацию и параметризованные запросы. База и артефакты размещаются в игнорируемом `data/`. Конфигурация не содержит настоящих ключей.
- [ ] Запустить `npx vitest run tests/db.test.ts`: все проверки проходят. Зафиксировать изменения коммитом `feat: persist companies and research runs`.

### Task 2: Очередь и отдельный worker

**Files:** `src/server/jobs.ts`, `src/worker.ts`, `tests/jobs.test.ts`, изменения `src/server/db.ts`, `src/domain/types.ts`, `package.json`.

**Interfaces:** `enqueueJob(runId: string, kind: JobKind, payload: unknown): Job`; `claimJob(workerId: string, now: number): Job | null`; `finishJob(id: string, result: unknown): void`; `failJob(id: string, error: JobError): void`; `cancelRun(id: string): void`. JobKind: discover, analyze, image. Job имеет статус pending/running/completed/failed/blocked/cancelled, attempts, leaseUntil. `processJob(job: Job, providers: Providers): Promise<void>` реализуется Task 3.

- [ ] Добавить тесты: одновременный захват даёт одного владельца; истёкшая аренда восстанавливается; максимум 3 попытки; отмена препятствует следующему этапу; отсутствующий провайдер даёт blocked без автоматических повторов. Запустить `npx vitest run tests/jobs.test.ts`, подтвердить ожидаемые ошибки.
- [ ] Реализовать атомарный захват транзакцией, аренду 120 секунд с продлением, backoff 5/30 секунд для временных ошибок, остановку worker по SIGTERM и проверку отмены между этапами. Worker запускается `npm run worker`.
- [ ] Повторить тесты до прохождения; коммит `feat: process bounded persistent research jobs`.

### Task 3: Источники, анализ и референсы

**Files:** `docs/providers.md`, `src/providers/contracts.ts`, `src/providers/search.ts`, `src/providers/analysis.ts`, `src/providers/images.ts`, `src/providers/config.ts`, `src/server/pipeline.ts`, `tests/pipeline.test.ts`, `tests/fixtures/providers.ts`.

**Interfaces:** `SearchProvider.discover(input: RunInput): Promise<DiscoveryResult>` и `verifyWebsite(company: Company): Promise<WebsiteEvidence>`; `AnalysisProvider.analyze(input: AnalysisInput): Promise<AnalysisResult>`; `ImageProvider.generate(input: ConceptInput): Promise<ImageArtifact>`. `Providers` содержит эти три адаптера. AnalysisResult: observations со sourceIds, uncertainties, competitorSourceIds, draftMessage, suitability. UsageRecord: provider, operation, units, cost, currency, costStatus confirmed/estimated/unknown. `getProviderStatus(): ProviderStatus[]` возвращает только имя, доступность и безопасную причину блокировки.

- [ ] Изучить официальную документацию Яндекс Maps Search API, допустимость выбранного использования и доступные поля; отдельно проверить источник веб-поиска, текстовую модель и генерацию изображений. В `docs/providers.md` записать ссылки, дату, необходимые ключи, ограничения, выбранные серверные API и цены либо отсутствие точной цены. Не покупать доступ. Если существенные права или возможности не подтверждены, оставить автоматический поиск blocked с конкретной причиной, не выдавать ручной режим за интеграцию.
- [ ] Добавить тесты с явными fixtures: отсутствие сайта остаётся uncertain без независимой проверки; неизвестные sourceIds отклоняются; внешние инструкции не меняют системные требования; недоступный ключ даёт blocked; неизвестная цена сохраняется как unknown; ошибка провайдера не раскрывает ключ. Запустить `npx vitest run tests/pipeline.test.ts`, подтвердить ожидаемые ошибки.
- [ ] Реализовать адаптеры по проверенной документации: таймауты 30 секунд для поиска и анализа, 120 секунд для картинки, лимит ответа, серверная проверка структуры, раздельные системные инструкции и внешний текст. Запросы направлять только на фиксированные адреса провайдеров; не скачивать произвольные URL пользователя. API-ключи хранить в переменных окружения, не логировать тела аутентифицированных ошибок.
- [ ] Реализовать processJob, сохранение подтверждённых источников и usage. Изображение генерируется только отдельным заданием по действию пользователя после анализа, сохраняется локально с безопасным именем, выдаётся как image/png или image/jpeg без исполнения содержимого. Ручной ввод допускает только валидированные поля и http(s)-ссылки и помечается manual.
- [ ] Запустить тесты. При имеющихся ключах выполнить реальный малый запрос каждого подключённого провайдера; иначе записать точную внешнюю блокировку. Коммит `feat: connect evidence-based research providers`.

### Task 4: Рабочий веб-интерфейс

**Files:** `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`, `src/components/run-form.tsx`, `src/components/company-list.tsx`, `src/components/company-detail.tsx`, `src/app/api/runs/route.ts`, `src/app/api/runs/[id]/route.ts`, `src/app/api/companies/route.ts`, `src/app/api/companies/[id]/route.ts`, `src/app/api/companies/[id]/concept/route.ts`, `src/app/api/status/route.ts`, `src/server/http.ts`, `tests/http.test.ts`, `tests/e2e/workflow.spec.ts`.

**Interfaces:** POST `/api/runs` принимает RunInput и возвращает run id; GET возвращает состояние, прогресс и расходы. PATCH company принимает только draftMessage и contactStatus (new/reviewed/rejected/contacted), с оптимистической проверкой версии. POST concept ставит отдельное задание. POST companies поддерживает ручной ввод. GET status выдаёт ProviderStatus без конфигурации ключей. Отмена запуска — DELETE `/api/runs/[id]`.

- [ ] Написать тесты HTTP: чужой Origin блокируется; limit 21 отклоняется; отсутствующий объект возвращает 404; неподдерживаемые поля и слишком длинный ввод отклоняются; конфигурация ключей не попадает в JSON; параллельное редактирование возвращает 409. Запустить `npx vitest run tests/http.test.ts` и подтвердить ожидаемые ошибки.
- [ ] Реализовать маршруты с Zod, ограничением размера JSON 64 KiB, проверкой same-origin для мутаций, безопасными ошибками. Сервер слушает loopback; документация запрещает открытое размещение без аутентификации.
- [ ] Создать русскоязычный адаптивный интерфейс: запуск, таблица с фильтрами статусов, детали источников и неопределённостей, редактирование и копирование сообщения, генерация и просмотр концепта, ручной статус обращения. Показывать свежесть данных, явные блокировки и отдельный индикатор тестового режима. Пустое состояние не заполнять фиктивными компаниями.
- [ ] Добавить Playwright-сценарий на отдельной временной БД с fixture-адаптерами: создание запуска, обработка отдельным worker, открытие компании, редактирование, картинка по действию, отмена и повторное открытие с сохранённым состоянием. Fixtures доступны только при явном тестовом флаге и не смешиваются с рабочей базой.
- [ ] Запустить `npx vitest run tests/http.test.ts` и `npx playwright test`: ожидается успешное выполнение реальных сценариев. Коммит `feat: add research review workspace`.
